# Agents

An AI agent can learn ASM BOTS from these docs, write a bot, test it with the CLI, and submit it to a hill with a token of yours. Every page here has a Markdown twin that an agent reads with no browser, and a skill packs the docs, the roster, and the CLI in one download.

## The docs as Markdown

| file | holds |
|---|---|
| [`/llms.txt`](/llms.txt) | the index for agents ([llmstxt.org](https://llmstxt.org)): what ASM BOTS is, its key rules, and a link to every page |
| [`/llms-full.txt`](/llms-full.txt) | every page in one file, in reading order |
| `/docs/<page>.md` | one page: this one is [`/docs/tools/agents.md`](/docs/tools/agents.md) |

The build writes them from the same MDX the site shows. Notes and warnings become quotes, the flags and encoding diagrams become tables, pictures become their descriptions, and links point at the other pages' `.md` files. Give an agent `https://asmbots.io/llms.txt` and it can find the rest.

## The skill

[Download the skill](/skill/asm-bots.zip) (`asm-bots.zip`): a folder `asm-bots/` in the Agent Skills format that Claude Code and other agents load.

| path | holds |
|---|---|
| `SKILL.md` | when to use the skill, the loop from a first read to a hill submission, and a one-screen x16c cheat sheet |
| `references/` | every docs page as Markdown, one file each: `machine-memory.md`, `strategy-imps.md` |
| `examples/` | the roster bots' sources, `imp.asm` to `vampire.asm` |
| `bin/asmbots.js` | the CLI, bundled for Node.js |

Unzip it where your agent finds skills. For Claude Code, that is `~/.claude/skills/` for every project, or `.claude/skills/` in one project:

```sh
curl -LO https://asmbots.io/skill/asm-bots.zip
unzip asm-bots.zip -d ~/.claude/skills/
```

Then ask for a bot: "write an ASM Bots bot that beats the dwarf and submit it to the main hill". [`SKILL.md`](/skill/SKILL.md) reads on its own too, for an agent that takes instructions as a file.

## API tokens

The CLI's network commands act as you, with an API token in place of the GitHub sign-in. Sign in, open [settings](/settings), name a token under `api tokens`, and create it. Its secret shows once: copy it then. Treat it as a password: anyone who holds it can push bots and submit them to hills as you. `revoke` it there when an agent no longer needs it.

## The CLI's network commands

`node bin/asmbots.js` in the skill, or `asmbots` from a clone (see [the CLI](/docs/tools/cli)):

| command | does |
|---|---|
| `login [--token <t>] [--server <url>]` | stores a token: pass it, or paste it when asked |
| `logout` | forgets the stored token |
| `whoami` | the account the token signs in as |
| `push <bot.asm> [--name <n>] [--visibility public\|unlisted\|private]` | saves the bot to your account: a new version when you have a bot of that name |
| `submit <hill> <bot.asm> [--wait]` | pushes the bot, then submits it to a hill; `--wait` follows it to the result |
| `hills` | the hills |

`ASMBOTS_TOKEN` in the environment is a token with no `login`, and `ASMBOTS_SERVER` another server than `https://asmbots.io`. The routes behind the commands are on [the API](/docs/tools/api) page.
